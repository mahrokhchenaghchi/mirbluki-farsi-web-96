# 📐 تحلیل، مهندسی معکوس و نقشه راه — پلتفرم سفارش آنلاین رستوران

> سند مرجع پروژه «پیتزا رویال» — بازطراحی مهندسی‌شده الگوی pizzasoli.ir برای هر رستوران دیگری، با تمرکز بر قابلیت توسعه و مدیریت حرفه‌ای.

---

## ۱) تحلیل سایت مرجع (pizzasoli.ir)

> ⚠️ **نکته مهم:** در زمان تحلیل (شهریور ۱۴۰۵ / سپتامبر ۲۰۲۶)، سرور سایت مرجع با **خطای 504 Gateway Timeout** پایین بود. تحلیل زیر بر پایه آرشیو وب (Wayback Machine)، ایندکس موتورهای جستجو و منابع جانبی (intoday.ir، googlemenu.ir، دلینو) انجام شده است.

### ۱-۱) چیستی و مدل کسب‌وکار

| مؤلفه | مشاهده |
|---|---|
| نوع کسب‌وکار | زنجیره فست‌فود چند شعبه‌ای (کرج: مهرویلا، جهانشهر + مازندران: تنکابن) |
| مدل سایت | سفارش آنلاین اختصاصی (بدون واسطه اسنپ‌فود/دلینو) + حضور هم‌زمان در اگریگیتورها |
| الگوی URL شعبه | `pizzasoli.ir/order/{branch-slug}` — مثلا `order/soli-tonekabon` |
| دسته‌های منو | پیتزا، ساندویچ، منوی صبحانه، منوی کافی‌شاپی |
| روش‌های سفارش | اینترنتی (سایت)، حضوری/میل در محل، بیرون‌بر، تلفنی |
| ارسال | ارسال رایگان در محدوده مشخص هر شعبه |
| ساعات | حدود ۱۰:۰۰ تا ۲۳:۳۰ بسته به شعبه |

### ۱-۲) امکانات شناسایی‌شده (Reverse Engineering)

1. **ساختار چندشعبه‌ای (Multi-Branch):** هر شعبه URL، منو، شماره تماس و ساعت کاری مستقل دارد.
2. **صفحه سفارش شعبه‌محور:** کاربر ابتدا شعبه را انتخاب می‌کند، سپس منوی همان شعبه را می‌بیند.
3. **ثبت‌نام و ورود کاربر** (فرم ایمیل/شماره تماس/رمز عبور — طبق فرم ثبت‌نام آرشیوشده).
4. **منوی دسته‌بندی‌شده** با قیمت‌های به‌روز هر شعبه.
5. **نقشه و مسیریابی** هر شعبه (لینک Google Maps / نشان / بلد).
6. **حضور در اگریگیتورها** (دلینو) به موازات کانال اختصاصی.
7. **SEO محلی:** عنوان «پیتزا سولی - سفارش آنلاین»، ثبت در دایرکتوری‌های محلی، Rich Data امتیازدهی (aggregateRating).
8. **شبکه‌های اجتماعی:** اینستاگرام فعال به عنوان کانال اصلی مارکتینگ.

### ۱-۳) ضعف‌های شناسایی‌شده (فرصت‌های ما)

| # | ضعف در مرجع | راه‌حل در این پروژه |
|---|---|---|
| ۱ | **پایداری سرور** — خطای 504 در لحظه تحلیل | استقرار استاتیک (CDN) + بک‌اند Managed (Supabase) بدون سرور نگهداری |
| ۲ | **ورود با ایمیل/رمز** — اصطلاحا «قدیمی» و پراصطکاک برای غذاسفارش | ورود با موبایل + OTP (بدون رمز عبور) |
| ۳ | **نداشتن سبد خرید مدرن و کشویی** | سبد خرید زنده با انتخاب سایز، یادداشت آشپز و کوپن |
| ۴ | **نداشتن ردیابی وضعیت سفارش** برای مشتری | صفحه پیگیری با تایم‌لاین ۵ مرحله‌ای و رفرش خودکار |
| ۵ | **نبود پنل مدیریت خودسرویس** (ویرایش منو نیازمند توسعه‌دهنده) | پنل ادمین کامل: منو، شعب، سفارش‌ها، کوپن، مشتریان، تنظیمات |
| ۶ | **نداشتن گزارش و تحلیل فروش** | داشبورد با نمودار درآمد، پرفروش‌ها و سهم وضعیت‌ها |
| ۷ | **تجربه موبایل بهینه نشده برای سفارش سریع** | نوار سبد شناور، افزودن سریع تک‌سایز، دیالوگ انتخاب سایز |
| ۸ | **نبود سیستم وفاداری/تخفیف قابل مدیریت** | کدهای تخفیف درصدی/مبلغی با سقف و حداقل سفارش |

## ۲) نقشه مهندسی معکوس → پیاده‌سازی

| قابلیت مرجع | پیاده‌سازی معادل در این پروژه | فایل‌ها |
|---|---|---|
| صفحه سفارش شعبه `/order/{slug}` | `/menu?branch={slug}` + انتخابگر شعبه در هدر منو | `src/pages/Menu.tsx` |
| منوی دسته‌بندی‌شده | ۹ دسته، ۲۵+ آیتم seed، جستجو، فیلتر گیاهی/تند/تخفیف | `src/pages/Menu.tsx`, `src/data/seed.ts` |
| چند شعبه با اطلاعات مستقل | مدل `Branch` با هزینه ارسال/حداقل سفارش/ساعت کاری/مختصات | `src/pages/Branches.tsx`, `admin/Branches.tsx` |
| ورود کاربر | OTP موبایلی (دمو: کد ثابت، واقعی: Supabase Auth) | `src/pages/Auth.tsx`, `src/hooks/useAuth.tsx` |
| سبد خرید | Context + localStorage، وابسته به شعبه، کشویی + نوار موبایل | `src/store/CartContext.tsx`, `src/components/CartDrawer.tsx` |
| ثبت سفارش | Checkout با ارسال/حضوری، ۳ روش پرداخت، آدرس، کوپن، یادداشت | `src/pages/Checkout.tsx` |
| (نداشت) پیگیری سفارش | `/track?code=RP-xxxx` با تایم‌لاین و رفرش خودکار | `src/pages/Track.tsx` |
| نقشه شعبه | دکمه مسیریابی Google Maps با مختصات | `src/pages/Branches.tsx` |
| (نداشت) پنل مدیریت | ۷ صفحه مدیریت با داشبورد تحلیلی | `src/pages/admin/*` |
| SEO محلی | متای فارسی، OG، robots.txt، ساختار headings | `index.html`, `public/robots.txt` |

## ۳) معماری انتخاب‌شده و منطق آن

```
┌────────────────────────────── React SPA (RTL, Vite) ──────────────────────────────┐
│  سایت مشتری (SiteLayout)                     پنل مدیریت (AdminLayout, lazy-load)  │
│  Home/Menu/Branches/Auth/                    Dashboard/Orders/Menu/Branches/      │
│  Checkout/Track/Account                      Coupons/Customers/Settings          │
└───────────────┬────────────────────────────────────────────┬─────────────────────┘
                │  React Query (useData hooks)                │
┌───────────────▼────────────────────────────────────────────▼─────────────────────┐
│  لایه داده یکپارچه — src/lib/db.ts  (api.*)                                      │
│  ├── حالت دمو: seed → localStorage (بدون هیچ تنظیم، قابل تست فوری)                │
│  └── حالت Supabase: جداول branches/categories/products/orders/coupons/...         │
│      (با env فعال می‌شود؛ در صورت خطا fallback به دمو)                             │
└──────────────────────────────────────────────────────────────────────────────────┘
```

**چرا این معماری؟**
- **قابلیت تعویض بک‌اند:** کامپوننت‌ها هیچ‌وقت مستقیم به Supabase وصل نیستند؛ فقط `api.*` را صدا می‌زنند. فردا می‌توانید به NestJS/Go/Laravel مهاجرت کنید بدون دست زدن به UI.
- **شروع بدون اصطکاک:** همین الان بدون دیتابیس قابل اجرا و دمو است؛ وقتی مشتری واقعی تأیید کرد، فقط دو متغیر env + یک migration لازم است.
- **قابلیت توسعه:** هر قابلیت جدید = ۱ فیلد در `types.ts` + ۱ ستون در migration + ۱ فرم در ادمین.
- **عملکرد:** کداسپلیت ادمین (recharts فقط برای مدیر دانلود می‌شود)، lazy image، staleTime برای کش.

## ۴) پیشنهادات بهبود تجربه کاربر (UX)

### ✅ پیاده‌سازی‌شده در این نسخه
1. **فرiction کم:** ورود بدون رمز با OTP؛ امکان شروع سفارش بدون ورود (ورود فقط در Checkout).
2. **افزودن سریع:** آیتم‌های تک‌سایز با یک کلیک به سبد می‌روند؛ چندسایزها دیالوگ انتخاب سایز.
3. **یادداشت هر آیتم** («بدون پیاز، پنیر اضافه...») — یکی از پرتکرارترین نیازهای واقعی.
4. **شفافیت هزینه:** هزینه ارسال، حداقل سفارش و سقف ارسال رایگان از همان صفحه منو نمایش داده می‌شود.
5. **اعتبارسنجی زنده سبد:** هشدار «حداقل سفارش» و «ارسال رایگان شد 🎉» قبل از Checkout.
6. **پیگیری بدون استرس:** تایم‌لاین + پیام‌های انسانی («پیک در راه است، گوشی در دسترس نگه دارید»).
7. **وضعیت باز/بسته** لحظه‌ای در هدر، هرو و کارت شعبه.
8. **اعداد و تاریخ فارسی** و فونت وزیرمتن در کل تجربه.
9. **404 برند‌دار** و صفحه خالی سبد با CTA.

### 🔄 پیشنهادات فاز بعد (اولویت‌بندی‌شده)
| اولویت | قابلیت | اثر |
|---|---|---|
| 🔴 بالا | **PWA (نصب روی گوشی + آفلاین منو)** | سفارش تکراری تا ۳۰٪ افزایش؛ نوتیف ارسال رایگان |
| 🔴 بالا | **سفارش مجدد با یک لمس** (Repeat Order) از تاریخچه | راحت‌ترین مسیر پول‌ساز مشتریان دائمی |
| 🟠 متوسط | **انتخاب زمان تحویل** (رزرو برای ۲ ساعت بعد / مهمانی) | باز کردن بازار مهمانی و رویداد |
| 🟠 متوسط | **بخش نظرات و امتیاز واقعی غذاها** بعد از تحویل | اعتماد + محتوای SEO |
| 🟠 متوسط | **منوی صبحانه/شب با ساعت‌بندی** (زمان‌محور) | مطابق رفتار مرجع؛ افزایش فروش ساعات کم‌ترافیک |
| 🟡 پایین | **باشگاه وفاداری (امتیاز به ازای تومان)** | نرخ بازگشت مشتری |
| 🟡 پایین | **گالری واقعی غذا + اسلایدر بنر قابل مدیریت از ادمین** | انعطاف کمپین‌های بازاریابی |

## ۵) پیشنهادات عملکرد و فنی

1. **کداسپلیت** (انجام‌شده): باندل ادمین/نمودارها جدا از مسیر مشتری — گیپ ۱۹۵KB برای سایت مشتری.
2. **تصاویر:** lazy-load + `aspect-ratio` ثابت (بدون Layout Shift). فاز بعد: تبدیل به WebP/AVIF با `<picture>` و `srcset`.
3. **کش سمت کلاینت:** React Query با `staleTime` و رفرش هوشمند (سفارش‌ها فقط در صفحات مرتبط poll می‌شوند).
4. **استقرار:** خروجی Vite کاملاً استاتیک است → CDN (Cloudflare Pages / Netlify / ابرآروان) + Supabase به عنوان BaaS؛ بدون سرور فیزیکی = خداحافظی با 504.
5. **امنیت:** کلاینت فقط anon key می‌بیند؛ RLS در سطح دیتابیس فعال است؛ مقادیر پولی سمت سرور باید در فاز عملیاتی دوباره اعتبارسنجی شود.
6. **پایش:** اتصال Sentry (خطاها) + Supabase Analytics (کوئری‌ها) پیشنهاد می‌شود.

## ۶) پیشنهادات پنل مدیریت (مدیریت حرفه‌ای)

### ✅ پیاده‌سازی‌شده
- **داشبورد روزانه:** تعداد/درآمد/میانگین سفارش، سفارش‌های در جریان.
- **نمودار ۷ روزه** درآمد و تعداد سفارش + دونات سهم وضعیت‌ها + پرفروش‌ها.
- **گردش کار سفارش:** pending → confirmed → preparing → delivering → done (+ cancel) با تاریخچه و زمان‌بندی.
- **جستجو و فیلتر** سفارش‌ها بر اساس کد/نام/شماره/شعبه/وضعیت + باز شدن مستقیم از لینک.
- **مدیریت منو بدون کدنویسی:** افزودن/ویرایش/حذف آیتم، مدیریت سایزها و قیمت هر سایز، تخفیف درصدی، برچسب تند/گیاهی/ویژه، قطع موجودی با یک سوییچ.
- **مدیریت دسته‌بندی** داینامیک (مثلاً افزودن «کباب» در آینده).
- **مدیریت شعب:** هزینه ارسال، حداقل سفارش، سقف ارسال رایگان، ساعت کاری، مختصات.
- **کوپن‌ها:** درصدی/مبلغی با سقف تخفیف و حداقل سفارش؛ فعال/غیرفعال.
- **CRM پایه:** لیست مشتریان با تعداد سفارش، مجموع خرید، برچسب «مشتری وفادار»، تماس مستقیم.
- **تنظیمات:** برند، شماره مدیر (سطح دسترسی)، پشتیبان JSON، بازنشانی دمو.

### 🔄 پیشنهادات فاز بعد برای ادمین
| اولویت | قابلیت |
|---|---|
| 🔴 | **نوتیفیکیشن سفارش جدید** (صدای زنگ + Browser Notification حتی وقتی تب باز است) |
| 🔴 | **چاپ خودکار فاکتور** (قالب ۵۸/۸۰ میلی‌متری پرینتر حرارتی) |
| 🔴 | **درگاه پرداخت واقعی** (زرین‌پال/آیدی‌پی) + ثبت خودکار پرداخت |
| 🟠 | **نقشه زنده پیک‌ها** و تخصیص سفارش به پیک (پنل پیک موبایل) |
| 🟠 | **مدیریت موجودی مواد اولیه** و هشدار اتمام |
| 🟠 | **گزارش‌ساز پیشرفته:** فروش بر اساس شعبه/دسته/ساعت + خروجی Excel |
| 🟠 | **کمپین پیامکی** به مشتریان غایب (۶۰ روز بی‌سفارش) |
| 🟡 | **سطح‌بندی دسترسی** (مدیر کل / سرشیفت / اپراتور ورودی داده) |
| 🟡 | **اپلیکیشن PWA ادمین** برای مدیریت از گوشی سرشیفت |

## ۷) دمو — چطور تست کنیم

| سناریو | مسیر |
|---|---|
| ورود مشتری | هر شماره معتبر + کد `123456` |
| ورود مدیر | `09120000000` + کد `123456` → آیکون کاربر → «پنل مدیریت» |
| ثبت سفارش | منو → افزودن آیتم (دیالوگ سایز) → سبد → ثبت سفارش → صفحه پیگیری |
| پیشرفت خودکار | سفارش دمو هر ~۱ دقیقه یک مرحله جلو می‌رود؛ ادمین هم می‌تواند دستی تغییر دهد |
| کوپن | در سبد، کد `WELCOME10` (درصدی) یا `ROYAL50` (مبلغی) |
| مدیریت منو | ادمین → مدیریت منو → ویرایش/افزودن آیتم → تغییر فوری در سایت |

## ۸) جمع‌بندی

نسخه فعلی، **همه قابلیت‌های محوری مرجع + مهم‌ترین نداشته‌های آن** (سبد مدرن، پیگیری، پنل ادمین، تحلیل فروش) را با معماری تمیز و قابل توسعه پیاده می‌کند و در دو حالت «دموی بدون بک‌اند» و «Supabase واقعی» قابل استفاده است. نقشه راه فاز بعد (پرداخت، PWA، پیک و…) در بخش‌های ۴ تا ۶ اولویت‌بندی شده است.
