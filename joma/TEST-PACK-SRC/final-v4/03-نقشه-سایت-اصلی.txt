۰۳ — نقشهٔ رفتن به سایت اصلی (فقط سند · هیچ اجرایی تا «برو»ی مالک)
=====================================================================
هدف این سند: وقتی خودت گفتی «برو»، بدانیم دقیقاً چه چیزی آپلود می‌شود، چه چیزی
نباید آپلود شود، چه خطری هست و چطور برمی‌گردیم. **تا آن روز، هیچ‌چیز روی
joma.mirbolouki.com تغییر نمی‌کند.**

──────────────────────────────────────────────
بخش ۰ — یک تصمیم که باید تو بگیری (سؤال، نه حدس)
──────────────────────────────────────────────
سایت اصلی دو حالت می‌تواند داشته باشد. باید بدانم کدام است:

  الف) **حالت فایل** — داده‌های فعلی کاربران داخل پوشهٔ data روی هاست است (مثل کپی تست).
  ب) **حالت MySQL** — داده‌ها در دیتابیس است و config/config.php مشخصات دیتابیس دارد.

از کدام استفاده می‌کنی؟ اگر نمی‌دانی: در cPanel → PhpMyAdmin ببین دیتابیسی به نام جوما داری یا نه،
یا در File Manager فایل config/config.php را باز کن و ببین خط «storage» چه می‌گوید:
  'storage' => 'file'   → حالت فایل
  'storage' => 'mysql'  → حالت دیتابیس
**بدون دانستن این، قدم بعد را برنمی‌دارم** (چون رفتار آپلود و پشتیبان‌گیری فرق می‌کند).

──────────────────────────────────────────────
بخش ۱ — چه چیزی روی سایت اصلی آپلود می‌شود
──────────────────────────────────────────────
همهٔ کدها و ظاهر و صفحه‌های تازه (همان چیزی که در بستهٔ test دیده‌ای) — چون سایت اصلی
هم همین اپ است و این‌ها نسخهٔ به‌روز همان فایل‌ها هستند:

  ▸ پوشهٔ pages/        (همهٔ صفحه‌ها: خانه، امروز، حال، جوجه، گزارش‌ها، دفترچه، حقوق داده، کنسول مدیر، …)
  ▸ پوشهٔ functions/    (+ water.php · insight.php · plancopy.php · recovery.php · jooje.php — فایل‌های تازه)
  ▸ پوشهٔ includes/     (layout.php · helpers.php · bootstrap.php · v2_*.php — قالب و کمک‌تابع‌های تازه)
  ▸ پوشهٔ assets/       (css/joma-v2.css · js/joma-v2.js · audio/br-*.mp3 — تازه)
  ▸ index.php           (مسیرهای تازه: journal · rights · admin_console · jooje)
  ▸ content/ · database/library_official.json   (آموزش + کتابخانهٔ ۱۰۷ فعالیتی)
  ▸ ۹ فایل صفحهٔ تازه که قبلاً نبود: journal.php · rights.php · admin_console.php · jooje.php و …

⚠️ **این‌ها نباید آپلود شوند:**
  · `config/config.php` — کانفیگ خودت (اگر MySQL داری، همان بماند)
  · پوشهٔ `data/` — دادهٔ کاربران واقعی. **هرگز جای‌گزین نشود.**
  · `_SEED-DEMO.php` — ابزار ساخت دادهٔ نمونه؛ روی سایت اصلی لازم نیست (و نباید باشد)
  · `tests/` — آزمون‌ها؛ روی سایت اصلی لازم نیست
  · `install.php` — اگر روی سرور هست، باید برداشته شود (خطرناک است)

──────────────────────────────────────────────
بخش ۲ — ترتیب کار (وقتی گفتی «برو»)
──────────────────────────────────────────────
۱) **پشتیبان‌گیری کامل** (من راهنمایی می‌کنم، خودت اجرا می‌کنی):
   الف) در cPanel → File Manager، از پوشهٔ سایت یک کپی zip بگیر (یا از Backup Wizard استفاده کن).
   ب) اگر MySQL داری: در phpMyAdmin → Export → دیتابیس جوما → Go (فایل sql دانلود شود).
   ⛔ **تا این پشتیبان سالم نباشد، قدم بعد را برنمی‌داریم.**
۲) آپلود بستهٔ اصلی (فایل zip ساخته‌شده برای همین کار) در ریشهٔ سایت → Extract.
   فایل‌های بالا جای‌گزین می‌شوند؛ config و data دست نمی‌خورند.
۳) اگر MySQL داری و جدول `joma_settings` نبود: فایل ADD-ONLY اختیاری را یک‌بار اجرا کن.
۴) اجرای صفحهٔ «بررسی سلامت نصب»: `https://joma.mirbolouki.com/health.php`
   → باید همه‌چیز «سالم» باشد. اگر چیز قرمزی بود، همان‌جا راه‌حلش نوشته شده.
۵) آزمون سریع با حساب خودت: ورود · داشبورد · کارهای امروز (یک ثبت آزمایشی) · گزارش‌ها ·
   حال من · جوجه · و یک نگاه به برنامهٔ ماه.
۶) اگر همه‌چیز درست بود: `health.php` و (اگر گذاشته بودی) `_SEED-DEMO.php` را پاک کن.

⏱️ زمان تقریبی: ۱۵ تا ۲۵ دقیقه، با پشتیبان‌گیری.

──────────────────────────────────────────────
بخش ۳ — ریسک‌ها و کاهششان (صادقانه)
──────────────────────────────────────────────
| ریسک | چقدر جدی است | کاهش |
|---|---|---|
| از دست رفتن داده در جای‌گزینی اشتباه | زیاد ولی کاملاً قابل پیشگیری | پشتیبان کامل + **هرگز** data/ و config.php جای‌گزین نشوند |
| ناسازگاری نسخهٔ PHP | متوسط | قبل از آپلود، `health.php` نسخه را گزارش می‌دهد؛ PHP 7.4 و 8.0–8.3 تست شده است |
| نبود افزونهٔ mbstring | کم | همان صفحه هشدار می‌دهد؛ بدون آن فقط ماژول هم‌مسیر محدود می‌شود |
| تفاوت دادهٔ قدیمی با ساختار تازه | کم | حالت فایل: دادهٔ قبلی خوانده می‌شود و «ثبت آب بدون وضعیت» = قطعی ✓ · MySQL: هیچ ستون/جدول تازه لازم نیست (فقط joma_settings اختیاری) |
| کاربران وسط کار باشند | متوسط | بهتر است در ساعت کم‌ترافیک انجام شود؛ جومای فعلی نشست‌ها را می‌بندد؟ نه — فقط کسانی که «رمز عوض کرده‌اند» بسته می‌شوند |
| برگشت به عقب | همیشه ممکن است | پوشه را از پشتیبان برگردان (۵ دقیقه) |

🔴 **چیزی که عوض نمی‌شود:** فرمول موفقیت، منطق ثبت روزانه/هفتگی/ماهانه، مجوزها، و هیچ دادهٔ کاربری.
🔴 **چیزی که تازه می‌شود:** ظاهر، صفحه‌های تازه، آب پیش‌نویس/قطعی، دفترچه، حقوق داده، کنسول مدیر.

بخش ۴ — پس از رفتن روی سایت اصلی: چه چیزی را خودت چک کن
──────────────────────────────────────────────
  □ ورود با حساب خودت انجام می‌شود
  □ یک ثبت در «کارهای امروز» می‌گذاری و در گزارش‌ها دیده می‌شود
  □ «حال من» را پر می‌کنی و ذخیره می‌شود
  □ «جوجهٔ من» را می‌بینی
  □ با موبایل هم باز می‌کنی (سایدبار می‌رود، نوار پایین می‌آید)
  □ اگر مشاور/همراه واقعی داری: میز کارش را می‌بینی و یادداشت خصوصی‌اش را نمی‌بیند
  □ «کد بازیابی رمز» را برای یک حساب تست امتحان می‌کنی (کاربر خودت)

بخش ۵ — آنچه برای رفتن لازم است تو بگویی (سه چیز)
──────────────────────────────────────────────

۲) آیا مشاور/همراه واقعی روی سایت اصلی فعال است؟ (تا بدانیم هم‌مسیر چه حالتی دارد)
۳) بازهٔ زمانی مناسب برای آپلود (تا کاربران وسط کار نباشند)
